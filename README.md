# 投标风险哨兵 Bid Risk Sentinel

> 面向投标从业者的合规风险自查工具：把"废标、投诉、刑事"三类雷区，在提交标书之前排掉。

**在线体验**：<https://tangyuxi-coder.github.io/bid-risk-sentinel/>
（免登录即可使用全部检测功能；登录后解锁云端同步与每日微信推送）

---

## 为什么做这个产品

招投标是一个"细节即生死"的行业：一份标书可能因为漏盖一个章、错过一个质疑期、踩中一条排他性条款而直接作废，甚至引发行政投诉乃至刑事责任。但从业者的现状是——法规散落在几十个文件里、截止期靠人工拿日历数、风险审查依赖昂贵的法律顾问。

法律专业背景让我熟悉这些规则，但**规则不该只存在于人脑里，应该被产品化**。于是有了这个项目：把招投标合规审查从"专业人士的经验"变成"任何人打开网页就能用的工具"。

## 核心设计决策

**1. 确定性规则引擎，而不是"问 AI"**

法律场景的底线是结论可追溯、可复核。大模型的回答每次不同、无法举证，因此产品的核心判断全部由写死在代码里的规则引擎完成——每条风险结论都能对应到具体法条（如《招标投标法实施条例》第 32 条），AI 交互层（哨兵助手）只做意图识别与任务调度，不产出定性结论。

**2. 隐私优先的纯前端解析**

标书是商业机密。所有文件解析（Word / PDF / 压缩包）均在浏览器本地完成，不出用户本机，从架构上杜绝数据泄露，也无需用户"信任"开发者。

**3. 渐进式架构：从纯前端 MVP 到全栈**

- v1：纯静态前端，验证核心检测能力，零成本上线
- v2：接入腾讯云开发（CloudBase），邮箱验证码免密登录 + 云数据库，实现跨设备同步
- v3：定时云函数每天 07:50 扫描全体用户台账，按各自的配置推送到期提醒与新标讯到微信，形成"网站巡检 → 云端存储 → 主动触达"的完整产品闭环

每一步都是"能用 → 上线 → 再扩展"，而非一次性大设计。

## 功能一览

| 模块 | 说明 |
|---|---|
| 哨兵助手 | 自然语言指令入口，本地意图识别调度规则引擎，对话式完成扫描与计算 |
| 项目看板 | 投标 / 保证金 / 质疑期三线倒计时，红黄预警，云端同步 |
| 标前排雷扫描 | 招标文件排他性条款、资质陷阱扫描，结论附法条依据 |
| 封装清单 | 自动提取签字、盖章、密封、份数等装订要求，生成核对清单 |
| 合同变脸检测 | 比对招标文件与合同的实质性条款偏离 |
| 围标 DNA 检测 | 多份标书文本雷同点分析 |
| 刑事风险自测 | 串通投标等刑事红线自查 |
| 计算器 ×2 | 诉讼费 / 利息数额计算、法定期间计算 |
| 法律库检索 | 招投标核心法规条文本地检索 |
| 每日推送 | 云函数定时巡检 + Pushplus 微信触达，按用户个性化配置 |

## 系统架构

```
浏览器端（React 19 + TS + Vite + Tailwind + shadcn/ui）
├── 规则引擎（法条正则库 / 截止日期计算 / 文本比对）
├── 本地文件解析（jszip / mammoth / pdfjs-dist，数据不出本机）
└── CloudBase JS SDK
        ↓ 邮箱验证码认证（免密）
腾讯云开发 CloudBase
├── 云数据库 userdata（安全规则：仅创建者可读写）
└── 云函数 dailyPush（定时触发 0 50 7 * * * *）
        ├── 扫描全体用户台账 → 7/3/1/0 天到期预警
        ├── 按关键词抓取当日新标讯
        └── 逐用户调用 Pushplus → 微信推送

部署：GitHub Actions → 自动构建 → GitHub Pages
```

## 技术栈

- **前端**：React 19 / TypeScript / Vite 7 / Tailwind CSS / shadcn/ui
- **后端**：腾讯云开发 CloudBase（认证 + 云数据库 + 云函数）
- **触达**：Pushplus 微信推送
- **CI/CD**：GitHub Actions → GitHub Pages

## 这个项目教会我的事（复盘节选）

- **报错信息是产品的一部分**：早期版本把云服务的错误对象直接渲染成 `[object Object]`，用户完全无法自助排查——错误提示必须翻译成人话，这是我修过的最有产品价值的一个 bug
- **外部服务的行为必须实测，不能读文档想当然**：邮箱"密码登录"实际发的是验证码、上传代码包会连带清除已装依赖，都是实测后才暴露的坑
- **部署链路本身是功能**：两套部署机制竞争导致线上随机白屏，让我理解了 CI/CD 的可重复性为什么重要
